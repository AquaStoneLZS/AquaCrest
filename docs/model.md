# AquaCrest 模型说明

本文对应 AquaCrest 1.0.0（特征版本 `aqua-1-crest-features-1`）。所有数值以 `src/frontend/shared/analysis/aqua-1-crest/model.js` 中的元数据为准；`release/model-metadata.json` 是同一份元数据的 JSON 副本。

## 推理流程

1. **范围检查**：解析 `.osu`，要求 Mode:3、4K、至少 80 个note、无格式错误；长条占比超过 18% 时直接拒绝（`UnsupportedLN`），不进入推理。
2. **倍速**：倍速不为 1 时，先把物件、timing、休息段和预览点的时间按倍速换算，再在 1.0× 下提取特征。已经带倍速的谱面文件按 1.0× 计算，不会从文件名再次套用倍速。
3. **特征提取**：生成 924 个特征，分三组。
4. **SVR 预测**：特征标准化、截断并按组加权后，经 RBF 核 SVR 得到难度。

## 特征

| 组 | 数量 | 距离权重 | 内容 |
| --- | --- | --- | --- |
| 结构 `structure` | 783 | 45% | 原始音符与长条结构：多押比例与强度、单手/双手的速度、jack、trill、指频、行频、疲劳、技巧、长条持有与释放、轨道与左右手不均衡、节奏熵与变化、按 1/4/16 秒窗口的局部峰值与分位数、BPM 与 SV 变化 |
| Azusa 曲线 `curve` | 139 | 35% | 对 Azusa 局部压力曲线的全部原始点做梯形加权编码：对数均值、RMS、峰值、分位数、17 个强度水平占比、32 段时间分箱、1–20 秒窗口峰值与高压持续比例；曲线不可用时用显式掩码置零 |
| 指标 `indices` | 2 | 20% | AquaTide 耐力 E 与 AquaReef 锚度 F 的对数值 |

特征只来自谱面内容；曲名、目录、作者、文件名和任何人工标签都不参与。结构特征与 Koishi 共用同一实现（`pattern-difficulty/`），AquaTide/AquaReef 来自 `aqua-ef-01/`（1.0.0）。

## 公式

记特征为 `f`，元数据中的 `mean`、`scale`、`factors` 为逐维向量，`clip = 8`，`γ = 0.35`：

```text
x_i = clamp((f_i − mean_i) / scale_i, −8, 8) × factors_i
y   = intercept + Σ_j coef_j · exp(−γ · ‖x − sv_j‖²)        # 2266 个支持向量，intercept ≈ 11.483
```

每组的 `factors_i = sqrt(组权重 / 组维数)`，因此三组在平方距离中的尺度分别按 45% / 35% / 20% 配置；这不是三个难度分数的加权平均，也不代表固定的输出贡献比例。

## 权重文件

`model.bin` 为小端 Float64 连续数组，`d = 924`、`S = 2266`：

| 顺序 | 内容 | 元素数 |
| --- | --- | --- |
| 1 | `mean` | d |
| 2 | `scale` | d |
| 3 | `factors` | d |
| 4 | `coefficients` | S |
| 5 | `supportVectors`，按支持向量逐行 | S × d |

共 16,790,576 字节，SHA-256 `cc87da936ecf9f662dbf11b38d52c4770eb7f2339d5e5cef75c8d9ec12c3c72c`。加载时校验大小、哈希、特征版本与布局，浏览器端另在读取后核对 SHA-256。

## 训练方式

AquaCrest 使用监督回归：把谱面提取为固定顺序的 924 维特征，以连续难度定数为目标，拟合 RBF 核支持向量回归（SVR）。

1. **特征准备**：提取结构、Azusa 曲线和 E/F 三组特征；不使用曲名、作者、目录或文件名作为模型输入。
2. **预处理**：使用拟合得到的逐维 `mean` 与 `scale` 标准化，截断到 `[-8, 8]`，再按组维数和距离权重缩放。训练后的这些参数随权重导出，推理时不重新拟合。
3. **回归拟合**：RBF 核使用 `gamma = 0.35`；导出支持向量、系数与截距。当前仓库未记录完整的参数搜索空间及 `C`、`epsilon`，不能据此精确复现原始拟合过程。
4. **分组验证**：开发阶段按关联分组划分训练与留出，避免同组跨越两侧；冻结辅助模型也不自动保证与留出输入独立，开发留出不等于独立盲测。
5. **导出部署**：将标准化参数、距离系数、回归系数与支持向量导出为 Float64，浏览器和 Node 共用推理实现。

E/F 作为冻结的辅助模型使用，其训练方式保留在 `aqua-ef-01/metadata.js`：

| 模型 | 训练方式 | 输入与合并 |
| --- | --- | --- |
| AquaTide（E） | 67 维标准化特征的线性模型，训练配置 `kind = positive`、ridge = 1 | 分别计算两只手的工作、疲劳与恢复特征，再按有效工作量合并 |
| AquaReef（F） | 137 维特征，180 轮、深度 1 的加法树模型，启用平衡设置 | 分别计算手内双指负荷偏向与持续结构，再按音符头数量合并 |

E/F 的开发验证方式为外层 5 折、内层 3 折的分组交叉验证。模型结构与方式描述用于理解现有权重，不构成独立准确性证明。

## 本地实现检查

`test/fixtures/synthetic.json` 只保存由 `synthetic-charts.mjs` 程序生成的人工键型及现有实现的输出快照，覆盖轮转、单手、连打、多押、节奏变化、休息、长条边界和倍速。

`npm test` 与 `npm run verify` 检查合成谱面回归、权重完整性和发布 ZIP 一致性。合成快照是实现回归检查，不是人工定数标签、独立准确性评估或 Python 参考一致性证明。

## 使用限制

- AquaTide 冻结模型仍有未解决的时长与休息段结构检查，其限制随 E 指标进入 AquaCrest。
- 长条占比超过 18% 的谱面不计算；当前入口在特征提取和推理之前拒绝。
- 预测超出训练标签范围（−1.93 至 18.3）时附带警告。
- 不同难度标尺的数值等价性没有独立证明，不能仅凭共同的回归目标认定它们完全一致。
- 预测值是模型估计，不是人工标签，也不代表视觉读谱、SV 或完整 LN 难度。
